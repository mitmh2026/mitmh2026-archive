    Solution to Dichotomies

    Answer: OVERLORD
    Written by: Dan Simon

    This puzzle is the meta for its set of minipuzzles, and looks somewhat different than the others. It contains:

    • the title "Dichotomies"
    • An example (labeled "Example:"), which says that (a triangle with [2nd] inside) = (a triangle with [00101] inside) = 20, shown below.
    • Eight equalities, where on the left side of each equality is something like "? (exactly)" or "?.3..." and on the right side of each is a tree diagram with a letter at the top and two shapes with ordinal numbers inside (similar to the triangle with [2nd] inside) as children of that letter. The first equality is also shown below as an example.
    ? (exactly) =

    In each of the minipuzzles leading into this meta, we had a tree diagram and examples of "x = [y]," and needed to figure out the rule leading from a number to its tree diagram (as hinted by the minipuzzle title, tree diagram, and examples) and then invert the rule on some input to get the answer. The minipuzzles are:

    • Dichotomies: CS (answer POPTART, solution link)
    • Dichotomies: CWT (answer ORBIT, solution link)
    • Dichotomies: LM (answer CLIQUE, solution link)
    • Dichotomies: RB (answer BERMUDA, solution link)
    • Dichotomies: RGC (answer KENDALL, solution link)

    Their tree diagrams are:

    We can write these more conveniently as:

    • Dichotomies: CS: f(x) = if (x = 1) then [] else ((x △ 2) concat f(if (x △ 2) then ((3 □ x) ○ 1) else (x ▭ 2)))
    • Dichotomies: CWT: f(x) = if (x = 1) then [] else ((x > 1) concat f(if (x > 1) then (x ⬭ 1) else (x ▭ (1 ⬭ x))))
    • Dichotomies: LM: f(x) = if (x = (1 ▭ 2)) then [] else ((x > (1 ▭ 2)) concat f(4 □ (x □ (1 ⬭ x))))
    • Dichotomies: RB: f(x) = if (x = 0) then [] else ((x △ 2) concat f(floor(x ▭ 2)))
    • Dichotomies: RGC: f(x) = if (x = 0) then [] else ((floor((x ○ 1) ▭ 2) △ 2) concat f(floor(x ▭ 2)))

    (See the solutions to Dichotomies: CWT and Dichotomies: LM for information on how to interpret "if.")

    To solve the puzzle, we need to notice several things. Firstly, as we probably used to solve some of the subpuzzles, the shapes in the tree diagrams denote arithmetic operations. We can easily deduce most of these via f(x) = if (x = 1) then [] else ((x △ 2) concat f(if (x △ 2) then ((3 □ x) ○ 1) else (x ▭ 2))), which we found implements Collatz sequences. Specifically, if (x △ 2) then ((3 □ x) ○ 1) else (x ▭ 2) is the next step in a Collatz sequence after x. This means △ is mod, □ is ×, ○ is +, and ▭ is /. ⬭ only shows up in CWT and LM, which are probably the hardest two minipuzzles, but process of elimination might lead us to believe it is likely -, and in both of those minipuzzle solutions we explain a path to determining it is - (though the path is much easier for CWT than for LM). There is a subtle symbol choice where + is to - as × is to / and similarly ○ is to ⬭ as □ is to ▭, but we are not expected to notice this.

    (Note that to allow us to still determine every symbol even without solving all the minipuzzles, every symbol shows up in at least two of the five minipuzzle diagrams.)

    In summary, we know △ is mod, □ is ×, ○ is +, ▭ is /, and ⬭ is -. If we haven't solved some minipuzzle, doing this substitution in its diagram will let us determine the function f for that minipuzzle (though we'll still need to invert it):

    • Dichotomies: CS: f(x) = if (x = 1) then [] else ((x mod 2) concat f(if (x mod 2) then ((3 × x) + 1) else (x / 2)))
    • Dichotomies: CWT: f(x) = if (x = 1) then [] else ((x > 1) concat f(if (x > 1) then (x - 1) else (x / (1 - x))))
    • Dichotomies: LM: f(x) = if (x = (1 / 2)) then [] else ((x > (1 / 2)) concat f(4 × (x × (1 - x))))
    • Dichotomies: RB: f(x) = if (x = 0) then [] else ((x mod 2) concat f(floor(x / 2)))
    • Dichotomies: RGC: f(x) = if (x = 0) then [] else ((floor((x + 1) / 2) mod 2) concat f(floor(x / 2)))

    We should also notice that our answers correspond to these shapes. Specifically:

    • Dichotomies: CS: A POPTART has a rectangular shape.
    • Dichotomies: CWT: An ORBIT has an elliptical shape.
    • Dichotomies: LM: CLIQUE shares a meaning with "circle."
    • Dichotomies: RB: The BERMUDA Triangle is a region of the Atlantic Ocean.
    • Dichotomies: RGC: KENDALL Square is a neighborhood of Cambridge, near MIT.

    Furthermore, we should note that the top letter of each diagram (O, C, P, K, K, O, P, B) is the first letter of one of our five answers. (The idea of using first letters is slightly hinted by the minipuzzle titles having acronyms of whatever concept they were based on.) Putting this all together, we can now create a correspondence between minipuzzles, minipuzzle number-to-bit-sequence functions, minipuzzle answers, first letters, shapes, and operations:

    So far we've noticed many things, but we have not actually understood the question-mark equalities, or the example. There are two main steps in understanding these things. The first is understanding the shapes with ordinal numbers inside (which the example helps with), and the second (easier) is understanding the top letters of each diagram.

    For understanding the shapes with ordinal numbers inside, we are told that (a triangle with [2nd] inside) = (a triangle with [00101] inside) = 20. It isn't immediately clear how [00101] is the 2nd of anything, but seeing "[2nd]" should make us think of indexing. Since we have a triangle, we take the answer corresponding to the triangle, which is BERMUDA, and index it to get the letter E, which corresponds to 00101 in binary. For how this corresponds to 20, we remember the bracketed bit sequences from puzzles. The conversion method corresponding to the triangle in the above table is reversed binary, so we interpret 00101 as reversed binary to get 20.

In our usual tree diagrams, we combine numbers with shapes representing operations, but here where we might expect a shape, we instead have the top letter of each diagram. As shown in the above correspondence table, these top letters correspond to the answers which they are the first letters of, which in turn correspond to shapes that correspond to operations.     Author's Notes

    Originally, I wanted to make a puzzle about large number notations such as those in AD Notations. However, this seemed unnecessarily obscure, and I thought it would overly benefit people who had already heard of it, so the idea slowly drifted away from pre-existing notations. By the time I actually started writing, I planned to use Hex notation in particular (which I had helped create), and the plan was to define other large-number notations in similar ways.

    Hex notation represents the binary strings it uses as hexadecimal strings instead, and pads with trailing 0 bits, but otherwise it can be expressed (almost) using the function representation system of this puzzle. Here it is:

    f(x) = if (x = 0) then [1] else ((x > 0) concat f(if (x > 0) then (floor(log2(x)) + x / 2^(floor(log2(x))) - 1) else -(floor(log2(-x)) + (-x) / 2^(floor(log2(-x))) - 1)))

    As you can see, this is significantly more complicated than the functions actually used in the puzzle. When finally drafted, the puzzle did not use Hex notation due to its complexity, but it had seven parts rather than five; it still included shapes representing 2^x and log2 in addition to the five operations it currently uses, and had some additional complicated and less-mathematically-founded functions.

    Over time, I edited to simplify the puzzle and reduce it to five functions, each based on a pre-existing mathematical or computer-science concept rather than invented de novo; thanks so much to testsolvers for suggesting simplifications.

    As in the current version, all functions in the original version had a consistent pattern of f(x) = if (x = a) then [] else (b concat f(c)), where the values for a, b, and c vary by minipuzzle. a is a specific value x for which f(x) = [], b is some expression that outputs 0 or 1 (or equivalently false or true), and c is some expression that outputs a number (not just 0 or 1). This consistent pattern is why the binary and Gray code are reversed; it's not as easy to write e.g. non-reversed binary starting from the left with a function like this. This pattern is not hard to notice and I think it makes the puzzle design nicer, but it is not very helpful for solving.
