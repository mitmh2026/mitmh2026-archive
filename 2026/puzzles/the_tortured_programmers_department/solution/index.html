    Solution to The Tortured Programmers Department

    Answer: CAPRI SUNS
    Written by: Kevin Der and Dan Simon
    Edited by: Benji Nguyen

    Introductory Steps

    This puzzle has six levels, plus one additional level that unlocks after solving 5 of these 6, and the answer submission tile. These levels all have a similar appearance. Each level has a subtitle which appears to be a word or phrase with most letters replaced by question marks, e.g. I ?????? ???? ??? ??????? or T?? O??????. In each level, there is a hexagonal grid with a number/punctuation mark in most cells, with some number of empty cells. There are also 8-12 tiles in the tile bank, each of which also has a number/punctuation mark (sometimes with multiple copies of the same one); the tiles can only be placed on the empty cells, and the number of tiles in the bank is always equal to the number of empty cells. Finally, one cell in each level has a rightward-facing arrow on its left. Each level also shows the overall puzzle title "The Tortured Programmers Department" and the text "Do not wrap."

    It's likely not immediately clear what most of this means, but the fact that the number of tiles to place is the same as the number of empty cells should let us conclude we somehow have to complete each level. To determine how to do this, we will need to have two realizations.

    The first realization is that this puzzle is related to Taylor Swift. The title being "The Tortured Programmers Department" should remind us of the Taylor Swift album "The Tortured Poets Department." Looking through the level subtitles, they do not match songs from The Tortured Poets Department, but they do match other Taylor Swift songs. Some of these song titles have distinctive word lengths, such as that of I ?????? ???? ??? ???????. These song titles confirm this idea; they may also be searchable enough with Nutrimatic to give the idea of Taylor Swift even without using the "The Tortured Programmers Department" title. A table of songs used in this step is below.

    (Indeed, the letters given are the minimum needed to find the song conveniently. The first letter of the title is always given. If the first letter and enumeration aren't sufficient to specify the song or the first word of the title is "The" (which is often ignored in alphabetical lists), the first letter of the second word is given (or the second letter of the first in the case of a one-word title). Also, whether the title is in title case or lowercase officially, the given letters are always in uppercase in this puzzle; this is to hint that, as seen later in the solution, some parts of the puzzle only work with capital letters. Also, the title of the level unlocked by solving 5/6 levels is not in this table and will be discussed later.)

    The second realization is that this puzzle is related to the programming language Hexagony. (The link is to an Esolang Wiki page describing the language.) This is somewhat harder than the first realization, but has multiple things pointing to it. Firstly, "Tortured Programmers" from the title points to Hexagony (it being a programming language with "agony" in the name). Secondly, the symbols used seem somewhat programming-esque but are clearly not a well-known language; due to the hexagonal grid in the puzzle, it's natural to use a programming language that is also on a hexagonal grid, and Hexagony is the most well-known. Hopefully, some combination of these facts leads us to the idea of using Hexagony. (The easiest combination if we are not already familiar with Hexagony is probably using "Programmers" to conclude this is about some programming language, and then searching something like "hexagonal programming language" to find which.)

    Once we have concluded that this puzzle is related to Hexagony, it is natural to conclude that each level is a program that we need to finish with the remaining characters. We of course need some way to find out what each program should do, but even before that, we need to determine some differences between Hexagony as it usually works and as it works in this puzzle. In usual Hexagony, the program is shaped like a hexagon, and there are six instruction pointers, one starting in each corner; there are some instructions to switch between them. Also, the instruction pointers move in lines through the hexagon (and can be redirected by various forms of mirrors); if an instruction pointer goes off the edge of the hexagon, there are rules about where it will wrap around to.

    The levels of this puzzle are not overall shaped like a hexagon, so the above needs to be altered. The instructions to switch between instruction pointers ([, ], and #) are not used in this puzzle, so we might conclude there is only one instruction pointer; this conclusion is furthered by the fact that in each level, one cell has an arrow pointing right, which we can take to signify the starting location and direction of the instruction pointer. Also, the wrapping rules do not make much sense for a non-hexagonal program shape, but the text "Do not wrap." suggests that we avoid wrapping at all, by not going off the edge in the first place. (This idea is also furthered by the fact that in many levels, already-positioned mirrors seem well-positioned to redirect us back into the program when we come close to coming off the edge. We might also think going off the edge means we halt, but Hexagony has an explicit halt instruction, namely @, so this seems less likely.)

    At this point, we understand the changes we need to make to Hexagony to understand how these programs run, but we still don't know what they should do. We can start by placing characters to just try to make the programs do something reasonable, and this might work to some extent, but it will be very difficult if not impossible to solve most levels solely in this way. In fact, we need to look back at the song titles. Each title clues some function that we can try to make the program implement. (Note that Hexagony does not have functions, so this is done by taking the input as the input string and printing the output.)

    Some of these song titles, such as "Blank Space," leave a large amount of ambiguity in what exactly the program should do, so looking at the part of the program already given (which is most of it) is also needed to narrow it down. In every case, there's no way to make a program with the remaining characters that does something else that can be described by the song title, even when both the given part of the program and the song title are ambiguous individually.

    Once we realize everything above (except for some vagueness about exactly what the programs do), we're ready to start solving levels. From here on, the solution will probably make more sense after reading the Hexagony wiki page also linked above. hexagony.net is also extremely helpful for visualizing what Hexagony code does. Note that hexagony.net has both "arguments" and "raw" output modes, which differ in whether the first character after input (character input, from ,) is 0 (an EOF) or -1. -1 is in accordance with the Hexagony spec, but by default hexagony.net will use "arguments" mode and include a 0. The programs will work regardless of this edge-case difference, though some will not work with empty strings in either case.

    The general method by which it's easiest to solve levels is to first place the characters controlling where the instruction pointer goes (control flow), and then place the rest. The control flow characters are /, \, |, _, >, <, $, and @. (^ would be on this list, but is not used in this puzzle; the same goes for [, ], and #, which switch between different instruction pointers as mentioned above). /, \, |, and _ are mirrors which the instruction pointer bounces off of; they do not depend on the memory grid. > and < are mirrors from some directions, but approaching them "head-on," they do use the memory grid to determine in which direction the instruction pointer turns; they are thus the primary way to e.g. break out of loops. $ jumps over the next character, and @ halts the program.

    Placing the control flow characters suffices to fully determine the instruction pointer path, and can largely be done without understanding what the program is supposed to do at all. It helps slightly to use the fact that all characters except . (which is a no-op) will be visited. Placing the rest of the characters is what determines program behavior, so in some sense it's the hardest part, but once all the control flow characters are known the program can be put into hexagony.net and run with the correct instruction pointer path (except for things like when loops are broken out of); the differences from standard Hexagony can be avoided by using mirrors to maneuver the instruction pointer to the starting position (as can be seen in the runnable program links provided later in this solution).

    Level Solutions

    Levels will be discussed below, in rough difficulty order (easiest to hardest). All levels but Blank Space will plausibly be unlocked relatively early.

    The Outside

    A hexagony.net link with the initial level state, with missing characters replaced by ], is here. A hexagony.net link with the correct solution is here. Both of these links have some extra mirrors and padding so we can run them as programs (though this admittedly makes it less clear where the edge of the program is), and the first has an extra @ in the top-right so that when the program hits a placeholder ], it will halt (specifically, it will switch to the next instruction pointer, which is in the top-right on the @). When reading the solution, it will likely help to refer to these links. Also, a screenshot of the solution as it appears in the tile round is at the bottom of this section, so we can more easily see which characters are missing and where the boundary of the program is.

    Recall from above that this level prints the first and last characters of the input, though this might not be clear initially from the title, and this is probably the easiest level to construct not knowing what it should do. (Note, however, that there are many ways to skip most of the program and have it only print the first character of the input.) This level has 8 missing characters (",/;;>@|): 4 control flow (/>@|), and 4 other (",;;). Once we place the control flow, we see that the program takes an input character, does something missing, enters a loop with a move in the memory grid and a something missing, then when it breaks out of the loop, does two missing things and halts. It's natural to use all of the input, and the only way to do this is to put the input (,) in the loop; with this placed, the loop makes a counterclockwise loop around a hexagon in the memory grid where the input is placed (overwriting parts of the input already placed if it's long enough). We have two remaining prints (;); it doesn't make much sense to print the final character twice, so probably the thing before the loop should be a print. We then have to order the remaining print and memory grid move; printing before moving will print an end-of-input character, so we move and then print.

    Mirrorball

    As with the previous level, a hexagony.net link with the initial level state, with missing characters replaced by ], is here. A hexagony.net link with the correct solution is here.

    Recall from above that this level reverses its input, though this might not be clear initially. This level has 8 missing characters (''/;<\{}): 3 control flow (/<\), and 5 other ('';{}). Placing the control flow, we make two loops that look somewhat symmetrical (both taking 7 characters); when we break out of one, it leads to the other, and when we break out of the other, it leads to halt (@). Interestingly, we start on a direct line towards the @, but of course we place a mirror to lead us into the first loop and prevent hitting @ so quickly. Once we place the control flow, we'll see that the program does something (X), enters the first loop with an input and 2 things missing, does X again on the way to the second loop (this character is traversed twice), enters the second loop with a memory grid move (") and two things missing (in the symmetrical places to where the first loop has things missing), and halts.

    The second loop does not output anything with the given characters; since we have only one print (;), for the second loop to not be completely pointless it should use the print. At this point, our four remaining characters are all memory grid movement; we have two in the top loop, one more in the bottom loop in addition to the " already there, and one that is the X mentioned above. Given the title "Mirrorball," even if we can't conclude that the program reverses its input yet, we may be led to believe that the program retraces its steps through the memory grid. This means that the characters in the bottom loop must undo those in the top loop; " undoes {, and ' undoes }, so the top loop must use the { to undo the already-there " in the bottom, and ' and } must be the other pair. By process of elimination, X is '. At the start of the program this is fine and basically does nothing, but when going between the loops, it means we must have recently done } to avoid going off track. This type of logic leads us to the full solution.

    Gold Rush

    A hexagony.net link with the initial level state, with missing characters replaced by ], is here. A hexagony.net link with the correct solution is here.

    Recall from above that this level adds AU at the end of the input, though it might not be clear initially that "Gold" in the title represents AU, or what to do with AU. This level has 10 missing characters ($/1567;;<>): 4 control flow ($/<>), and 6 other (1567;;). At this point, we might start to recognize a common small loop pattern with two slash mirrors and two branches, having seen two such loops in Mirrorball (though of course we may have done this and Mirrorball in the other order). This lets us place a branch (<). We may also realize that to enter this loop, we want to place an initial jump ($). Placing the rest of the control flow, we see that the aforementioned loop has an input (,) and a missing character, and we also have a lot of stuff after the loop. If we put a digit in the loop, it will just get written over by the input, so it makes the most sense to put print (;) in the loop instead. Our execution path after the loop (ignoring mirrors/branches which are just for control flow) is *??X??~X, where X is a ? that is passed through twice and is the same both times, and we have 1567; remaining.

    This is fairly ambiguous as stated, so at this point we need to use the fact that the program does something with AU. The * is initially confusing, but we can eventually realize that its purpose here is just to zero our current memory edge (since both inputs of * are unwritten to and are thus 0 by default) so we can consistently write numbers. (Recall that hexagony.net has two modes which differ in the value , writes after exhausting input; for convenience the program is written to not depend on this.) We may notice that 65 is the ASCII code for A, so starting with 65; (which sets current cell to 65 and prints it) sounds good.

    We still have the 1 and 7. We can try both options and run them in hexagony.net, and see which order works. In fact what the program does is writes 6571, negates it, and prints it, but Hexagony prints mod 256 so -6571 becomes 85, which is the ASCII code for U. (Hopefully we understand that the "Do not wrap." refers only to the instruction pointer, and that taking things mod 256 in this way is still allowed.)

    Mean

    A hexagony.net link with the initial level state, with missing characters replaced by ], is here. A hexagony.net link with the correct solution is here.

    Recall from above that this level takes the mean (average) of the ASCII values of its input, and outputs it (as a character). This is the most natural interpretation of "mean" (other than taking in numbers/outputting as number, but there are specific Hexagony commands for number I/O not used in this program). Also, one of the missing characters, :, does division, which should help solvers realize what this level does.

    This level has 10 missing characters (*+//:;\\}}): 4 control flow (//\\), and 6 other (*+:;}}). The control flow is four mirrors; we place one in a corner because nothing else can go there without then going off the edge, and we place three towards the end to use a hard-to-reach mirror. Placing the control flow, we see that this program has a fairly big loop, and then a decently long section which turns out to mostly be mirrors (non-mirrors are '"??) after the loop. (This end section uses unnecessarily many mirrors to take up space and make the regions fit together better.)

    We have just one ; so, similarly to The Outside or Mirrorball, it's reasonable to use it at the end so we don't have wasted operations at the end. To place the :, solvers are expected to realize the program computes the mean, and thus the : should go at the end (divide sum of values by length), just below the print. As for the other four characters, they're in the loop.

    There is a part of the loop where we add one (close parenthesis; we can assume this is for computing length), do two things, and then take input. We have *+}} remaining. If we do * or + just after adding one, then we will overwrite the result of the addition. On the other hand, if we do * or + just before taking input, then we will overwrite what we did with the * or + with our input. Neither of those things make sense. So probably both things between adding one and taking input are }. We still need to place the * and + in the two remaining cells, but thinking about it or using hexagony.net, we see that one option overwrites our input with 0 via * (via multiplying two values one of which is 0) and never actually creates anything nonzero (other than the length counter), while the other option dances around a few cells to maintain a running total of ASCII values, which is exactly what we need for the mean.

    I Forgot That You Existed

    A hexagony.net link with the initial level state, with missing characters replaced by ], is here. A hexagony.net link with the correct solution is here.

    Recall from above that this level removes all occurrences of the letter U from the input. "You" being U is strong enough that it is probably initially clear the program should do something with the letter U, but removing all occurrences might not be as clear.

    This level has 10 missing characters ($%'+489<\|): 4 control flow ($<\|), and 6 other (%'+489). The jump ($) is the hardest control flow character to put in, but the other three make it clear there's a big loop and the only way to get out is to halt, so we position the $ at the last possible place before the loop so we can visit everything before it. Having positioned the control flow, we see that this loop, unlike previous loops, has a branch in it that re-merges. At this point, we should conclude that this branch checks if the most recent input is U, a conclusion furthered by the fact that the only difference between the branches is that one side of the branch prints and one doesn't (all of the missing characters in the loop are before the branch).

    But how can we check this? Hexagony doesn't have an equality operator. Looking at our program and character bank, the most promising option is a % (modulo). But we don't have any obvious way to get the codepoint of U (85); we have a 4, an 8, and a 9, and though 89 - 4 = 85, there's no minus or negation anywhere. After enough thought, we should realize that the only thing that works is to add 4 and take mod 89. To avoid overwriting or complicating our input, our only option for the thing we do after , is '. We need to add 4 in the loop, so the loop needs to have a +. This puts the 4, 8, and 9 all before the loop, and the fact that we need to write the 8 and 9 to the same cell (and in that order) lets us fill out the remaining cells.

    Note that if we actually look at what the program does in detail, we may be surprised to find that the program does not take (input + 4) mod 89; it takes 89 mod (input + 4). This is to avoid any false positives; the only possible character code x for which 89 mod (x + 4) = 0 is 85. This would not be true for e.g. (x + 4) mod 89 (174 would also work) or for 85 mod x (1 would also work). Unrelatedly, we may also be surprised that the program passes through the 9 twice, but the second time, the 9 is just overwritten by input.

    Blank Space

    A hexagony.net link with the initial level state, with missing characters replaced by ], is here. A hexagony.net link with the correct solution is here.

    This program is the largest and most complicated by a decent margin. Above we said that this program replaces the middle letter (rounding down) with space, but unfortunately for us, there is no way that we know this at this point; all we know from the title "Blank Space" is that it involves spaces in some way. In practice it is likely that we will skip this level, but it does unlock some useful adjacencies in other puzzles, so it may be worth solving for that reason.

    This level has 12 missing characters (&/23:;<=>@\|): 6 control flow (/<>@\|), and 6 other (&23:;=). The control flow other than the @ is not that bad to place; the @ is a bit tricky since even though it does go on a dead end in practice, seeing that it's on a dead-end requires seeing that the other mirrors have to be used elsewhere (otherwise it might be possible to put a mirror there instead). The @ is also tricky because we go through some random characters to get to it which as it turns out don't have any effect and might seem useless. But this is fine since those characters are used on other paths through the program. Once the control flow is placed, we find that the program has a three-loop structure, with some code between the loops.

    The given 3 and 2, which make the character code for space, should presumably be adjacent; there's only one place to put them, in the first loop. (This was actually almost true before the control flow was placed; there had been a group of two adjacent cells filled by control flow. That being said, the 3 and 2 couldn't go there, because if they did then they would be overwritten by the + or the % along the path.) Our other four missing characters are distributed as follows: one between the first and second loops, one in the second loop and also (in another direction) between the second and third loops, and two (adjacent) in the third loop. Even though we already know printing (;) is not the literal last thing we do, if it's not in the third loop then it's pointless, so we assume ; is in the third loop.

    Looking at the second loop, the memory pointer moves like '"=?, where ? is missing. By running the program using hexagony.net, we can already conclude that the memory pointer in the first loop moves linearly in input length, rather than staying in one place. If ? is a non-memory operation, the second loop stays in one place. If ? is =, the second loop retraces the first loop's steps, which seems more promising. So we use = in the second loop. Looking at what actually happens, we see = is undone by another = both times it's used, which may seem worrying, but it's actually doing a complicated thing allowing us to zero a cell with * and thus use a pre-placed & to copy the left neighbor.

    To place the remaining three characters, it's unclear how to use the cheap tricks we've often been using to not fully understand the program (e.g., we can't just look at the pointer movement in memory, or try to make the arithmetic operations seem like they work out, or try to avoid overwriting things in a clearly useless way). The only real options are either deeply understanding the program, or trial and error in hexagony.net (or with the answer checker). Basically, the : is between the first and second loop and is dividing roughly the length of the string by 2 to decide where to position the space, and the & and ; are in the third loop (in that order) with the & determining whether to put a character from the string or a space in the current cell, and the ; printing whichever is chosen. Overall, the first loop inputs the string and also writes a count of characters so far to memory (and writes spaces to memory, hence 32 being in the first loop), the second loop goes back through the string and writes the halfway point to memory everywhere, and the third loop goes forward again, compares the count of characters to the halfway point with modulo tricks, and prints a space when they're equal and the input character otherwise.

    The Moment I Knew

    A hexagony.net link with the initial level state, with missing characters replaced by ], is here. A hexagony.net link with the correct solution is here.

    This level has 12 missing characters ("$''(../<>\_): 6 control flow ($/<>\_), and 6 other ("''(..). As usual, the control flow is not too bad; half of it is on the left side of the program and fairly quick to put in, there's one < that leads to an @, the _ is placed near the bottom where the alternative is hitting a mirror and doing a fairly large backtrack (which would be surprising), and the $ is placed to similarly avoid a backtrack and jump over another control flow operator (>).

    Once we've placed the control flow, we see that there's a loop on the top and another on the bottom, and we can exit either by going to the other or by going to an attached @. We can fairly easily conclude that the ( goes right after the top loop's branch that can lead to halting, since otherwise it turns out to be impossible to get to the bottom loop.

    There are two ways to fill in the remaining other characters. One way is to notice that there is a sort of symmetry in the actual instructions that are done, even though the paths through the program are not symmetric; in a sense, if we rotate the program 180 degrees and swap the loops on the top and bottom, and also swap ' and ", everything is the same. For example, the bottom loop does ?("+XY, and the top loop does ?('+Z"Z. If we take X = ', Y = ., Z = ., this becomes ?("+' and ?('+".

    The other way is to use the "back and forth" line to conclude that we go in a rough line in each of the top and bottom loops, and we switch direction 180 degrees when we go between them. The actual logic for this is very hard, but we can experiment in hexagony.net to pin things down. (There are 30 options for how to place the remaining characters, but we can e.g. focus on one loop at a time so we don't have to try all 30.)

    It is worth noting that unlike for the other programs, there is no input that visits every character other than the periods. This is almost true, but there is the exception that of course, no single input can visit both occurrences of @. The given input ends at the top @, but other inputs will end at the bottom @.

    Whatever method we use to finish the program, we should run it on the given input. Generally speaking, the program draws lines of numbers one less than those in its input (writing each number in two memory edges), with the exception that for a 1 in its input (or values less than 1), it will move over slightly and reverse direction rather than continuing to go straight.     Some of the choices in the program, e.g. the initial { turn and the + when going from one loop to the other, are made specifically to make the output look better in hexagony.net, since it is by far the easiest way to view the memory grid. If we are viewing the memory grid in some other way, e.g. manually running the program, our result may be empty where this has zeros (empty and zero are practically the same in the Hexagony memory grid), and also may be rotated.

    Now, we notice that if we take CAR LESS as distinct words, we have output words of length 1 through 7. The output from The Moment I Knew, which we have not yet used, has seven lines with pairs of memory edges with 1 or 2, and these lines also have 1 through 7 pairs of memory edges. For example, the top line has 3 pairs (a pair with 2, another pair with 2, and a pair with 1), and the next has 2 pairs (a pair with 2 and then a pair with 1).     Author's Notes

    Dan: Writing the programs for this puzzle was tedious but in the end not very conceptually hard. They all use the same style of loops and paths between the loops, with mirrors needing to take up a decent amount of space. In real Hexagony I think you can do more complicated things with wrapping around and switching instruction pointers, but given the (somewhat self-imposed for clarity) restrictions of no wrapping and only one instruction pointer, I don't really know how to make the programs more varied. I feel like I still don't really understand how I "should" write Hexagony. Some of the programs are slightly more complicated than needed to make them fill the level; this doesn't add too much interesting behavior for solvers, but it does cause there to be fewer vast areas filled with periods.

    As mentioned above, Blank Space is more complicated than the other programs. The only ways I know to do it require three loops, though maybe there's some trick to store the input as a huge integer and get it down to two. I was somewhat worried this program would be too complicated, but though neither of two testsolves found it, when I organized a Blank-Space-only testsolve with past testsolvers who skipped it, they only took slightly more than an hour.

    Spoiler warning: info about adjacent puzzlesThe levels are arranged so that every level other than Blank Space is accessible from either Lifecycle or Case of the Superhero Dinner Party. This was somewhat intentional to allow solvers access to many levels at once. The part of Case of the Superhero Dinner Party that needs to be solved to get access to two levels (T?? O?????? and ME??) is not that hard, though, so solvers will probably first encounter this puzzle with just those two levels. As mentioned above, T?? O?????? is one of the easier levels, so this is a reasonable starting point even without solving Lifecycle.

    The decision not to use letters in the programs (which write their codepoint to the cell, overwriting it) is aesthetic; there are a few places where they would be convenient and a few more where they could add interesting complexity, but it wasn't that hard to just use numbers instead.

    This puzzle definitely involves more trial-and-error and guesswork than it involves logic, which I didn't fully realize until writing this solution and realizing how hard it is to justify anything logically. The fact that solvers often had to try several options for a level should have probably clued me in. The song titles not fully pinning down behavior further complicates things.

    I wrote a Python Hexagony interpreter/brute-forcer while writing the solution due to getting fairly worried I could have missed a case. The Enchanted line "And now I'm pacing back and forth." was added at this point (not earlier) to further pin down The Moment I Knew for solvers who didn't notice the symmetry in program structure. All the other programs seemed fairly clear given the title (though it helps to make an assumption of no unused characters; without it, Blank Space could just print a space), but I still think there's roughly a 20% chance I missed some option somewhere. If so, I'm sorry and hope it was possible to correct.
